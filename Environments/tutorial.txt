ACTION-RESPONSE DELAY EXPERIMENT -- COMMANDS
================================================================================

The experiment is now a SEED STUDY: three conditions, five independent training
runs each. One run per condition could not tell whether a difference came from
the delay training or from the luck of that run -- two earlier sweeps disagreed
with each other by more than their own confidence intervals.

The full plan, with every command spelled out, is in temporary.txt. This file is
the short version plus the tooling around it.

--------------------------------------------------------------------------------

--------------------------------------------------------------------------------

    python -m Environments.main.test_delays

--------------------------------------------------------------------------------
ENVIRONMENT SETTINGS FOR THIS EXPERIMENT
--------------------------------------------------------------------------------

    rho                   1/20000 - 1/10000   sectors 372-678 NM across
    crossings_per_episode 2.0                 episodes 1190-2171 steps
    seed_traffic_inside   True                reset scatters traffic through the
                                              sector on random headings instead
                                              of lining it up on the boundary
    advisory delays       redrawn only when the ADVICE CHANGES; repeating the
                                              advice already standing costs workload but
                                              does not restart the assessment

    Results from before these settings are not comparable with results after.

    # With --n-envs 1 each run has one stream, but that is not enough on its own. The stride
    # (7919) is coprime with the pool (5,000,000), so every run walks the whole pool before
    # repeating and two runs are shifted copies of the same cycle -- they must meet eventually.
    # How far in depends on the gap between the seeds:
    #
    #     gap 1     -> first shared episode after   17,679 episodes
    #     gap 1000  ->                            2,321,000
    #     gap 2000  ->                              358,000   (the worst pair here)
    #     gap 3000  ->                            1,963,000
    #     gap 4000  ->                              716,000
    #
    # A 100M-step run is about 59,000 episodes, so with these seeds nothing is ever shared --
    # a factor of 6 of headroom. Consecutive seeds would start sharing scenarios inside a long
    # run, which is why they are spaced.
    #
    # With more than one env there is a second reason: --seed reaches worker i as (seed + i), so
    # seeds 0 and 1 would hand the same stream to two different runs from the first episode.

    # The same seed in different conditions still sees the same scenarios, which
    # is deliberate: paired across conditions, independent across seeds.

    # 100M is a CEILING. Stop the runs by hand; Ctrl-C saves final_model through
    # the finally block, kill -9 does not. Stop all 15 at the SAME STEP COUNT,
    # not at the same time of day, or the comparison measures the budget instead
    # of the seed. Write down where each run stopped.

    # --n-envs 1 makes PPO's rollout 4096 rather than 8192 (n_steps is per env).
    # Fine, but it must be the same for all 20 runs.
