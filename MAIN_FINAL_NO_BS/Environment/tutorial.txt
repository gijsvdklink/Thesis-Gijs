# Run everything from the MAIN_FINAL_NO_BS folder:
#     cd <wherever MAIN_FINAL_NO_BS is>
# Check you are in the right place -- this must list Environment, Training, Validation:
#     ls
#
# Every run trains on one environment, as reported: a rollout of 2048 decision steps, updated
# as one batch of 2048 for 30 epochs. Torch runs single-threaded, so one run keeps about one
# core busy and the 21 terminals below need 21 cores.
#
# Every run stops after 60,000 finished episodes, about 8.5e7 decision steps. That is the
# default, so no step count has to be given: --max-episodes 60000 is only needed to train a
# different length. The count is logged to TensorBoard as episode/count, and each run prints
# its progress in episodes.
#
# This folder flies the kinematic traffic model of Environment/traffic.py instead of BlueSky,
# which is the only difference from MAIN_FINAL_BS. The model was measured against BlueSky's
# A320 at FL350 and agrees to 0.016 NM over 200 s; Validation/validate_kinematics.py repeats
# that check. Train here, then test the checkpoints in MAIN_FINAL_BS if the results are to be
# reported against BlueSky.
#
# Measured back to back on one laptop core: the whole loop (traffic, the policy and the 30
# update epochs) runs at 415 decision steps/s here against 101 with BlueSky, so 4.1x faster.
# An episode is roughly 1,400 to 1,600 steps, that is 2 h of simulated time and about 3.5 s of
# wall clock, so 60,000 episodes take about 2.5 days per run instead of 9 to 10. Check the
# steps/s and eta that each run prints.

================================================================================
RESUMING AFTER A DISCONNECT
================================================================================

# Same commands, plus --resume. Each run continues from its own last checkpoint,
# keeping the step count and the TensorBoard curves continuous. At most
# --save-every steps (500,000) are lost per run.
#
# Do NOT delete ../Models. Do NOT pass --overwrite; that starts from scratch.
#
# The episode counter is NOT stored in the checkpoint: it restarts at zero, so a resumed run
# would train another 60,000 episodes. Read episode/count for that run in TensorBoard and
# pass what is left, e.g. 60000 - 41000 = 19000 -> --resume --max-episodes 19000.

#     python Training/train.py --delay none --seed 1

#
#     tmux ls                         # list sessions

# The same 21 runs, but PPO with Stable-Baselines3's own defaults: nothing is set except the
# seed, the TensorBoard log and the CPU. That is n_steps 2048, batch_size 64, n_epochs 10,
